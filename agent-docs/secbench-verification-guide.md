# SEC-bench Verification Guide

This guide explains how to verify that Arise's outputs are compatible with SEC-bench's verification system.

## Overview

Arise's tree-structured agents (Builder, Exploiter, Fixer) generate outputs that can be verified using SEC-bench's `secb` commands. This allows comparison of success rates between:

1. **Arise system** (tree-structured multi-agent)
2. **SEC-bench baseline** (single-agent per phase)

## Quick Start

### 1. Run Arise with CVE Instance

```bash
cd deployment
docker compose --profile dev exec app-dev python main.py run \
  "Reproduce and fix the vulnerability" \
  --cve-file data/sec-bench/instances/faad2.cve-2018-20195.json
```

After execution, you'll see verification instructions with the container ID.

### 2. Manual Verification

```bash
# Container ID is printed after task completion
CONTAINER_ID="<from-arise-output>"

# Verify Builder output
docker exec $CONTAINER_ID secb build
# Expected: "BUILD COMPLETED SUCCESSFULLY!"

# Verify Exploiter output
docker exec $CONTAINER_ID secb repro
# Expected: Sanitizer error (vulnerability triggered)

# Verify Fixer output
docker exec $CONTAINER_ID secb patch
docker exec $CONTAINER_ID secb build
docker exec $CONTAINER_ID secb repro
# Expected: No sanitizer error (vulnerability fixed)
```

### 3. Cleanup

```bash
docker stop $CONTAINER_ID && docker rm $CONTAINER_ID
```

## Dual Verification Approach

Two verification methods test different aspects:

### Method A: Arise-Generated secb.sh

Tests: "Can our agents generate correct verification commands?"

Workers create `/testcase/secb.sh` based on prompt instructions.

```bash
docker exec $CONTAINER_ID chmod +x /testcase/secb.sh
docker exec $CONTAINER_ID /testcase/secb.sh build
docker exec $CONTAINER_ID /testcase/secb.sh repro
docker exec $CONTAINER_ID /testcase/secb.sh patch
```

### Method B: SEC-bench Original secb_sh

Tests: "Are our outputs structurally compatible with SEC-bench?"

Inject the original `secb_sh` from the CVE instance JSON:

```bash
# Extract secb_sh from CVE JSON and inject into container
docker exec $CONTAINER_ID bash -c "cat > /usr/local/bin/secb << 'EOF'
$(cat data/sec-bench/instances/faad2.cve-2018-20195.json | jq -r '.secb_sh')
EOF
chmod +x /usr/local/bin/secb"

# Run verification
docker exec $CONTAINER_ID secb build
docker exec $CONTAINER_ID secb repro
docker exec $CONTAINER_ID secb patch
```

### Result Interpretation

| Arise-generated | SEC-bench original | Meaning |
|-----------------|-------------------|---------|
| Pass | Pass | Full compatibility |
| Pass | Fail | Files in wrong locations |
| Fail | Pass | Agent misunderstood task |
| Fail | Fail | Fundamental issue |

## Expected File Structure

After execution, `/testcase/` inside the container should contain:

```
/testcase/
├── base_commit_hash     # Builder: git commit hash
├── repo_changes.diff    # Builder: source modifications (if any)
├── packages.txt         # Builder: installed packages (if any)
├── repro.sh             # Exploiter: reproduction script
├── model_patch.diff     # Fixer: vulnerability patch
├── output.jsonl         # Fixer: OpenHands format output
├── preds.json           # Fixer: SWEA format predictions
└── secb.sh              # Helper script (if generated by workers)
```

## Comparing with SEC-bench Baseline

SEC-bench reports results as (builder, exploiter, fixer):
- Example: `(true, false, false)` = Only builder succeeded

Arise results should show improvement:
- Example: `(true, true, true)` = All phases succeeded

## Troubleshooting

### Container Not Starting

```bash
# Check if SEC-bench image exists
docker images | grep secb

# Pull if missing
docker pull hwiwonlee/secb.eval.x86_64.faad2.cve-2018-20195
```

### Files Not Found in Container

```bash
# Check container's /testcase directory
docker exec $CONTAINER_ID ls -la /testcase

# Verify mount
docker inspect $CONTAINER_ID | jq '.[0].Mounts'
```

### secb Command Not Found

```bash
# Re-install secb from CVE JSON
docker exec $CONTAINER_ID bash -c "cat > /usr/local/bin/secb << 'EOF'
$(cat data/sec-bench/instances/<instance>.json | jq -r '.secb_sh')
EOF
chmod +x /usr/local/bin/secb"
```

## Architecture

```
arise-app-dev Container
    │
    ├─ CLI starts SEC-bench container with volume mount
    │      docker run -d -v output/{id}:/testcase {docker_image}
    │
    ├─ Workers execute commands inside container
    │      docker exec {container_id} <command>
    │
    └─ After completion: container stays running
           User runs manual verification
           User stops container when done
```
