Confirmatory Experiment Design Report

N1 versus B4: naive OpenHands against the complete adaptive system

A paired SEC-bench protocol with common solver objectives, common submission artifacts, and one arm-independent post-run evaluator. N1 receives no in-run Host mechanics; B4 receives the full hierarchy, role routing, procedures, and bounded recovery.

Design amendment · 2026-07-14Status: draft · not launchedPrimary contrast: B4 − N1Current result: none
01 / Research question and protocol

Does the complete B4 system outperform naive OpenHands?

Research question. Under identical SEC-bench assignments, submission requirements, and post-run evaluation, does the complete B4 system achieve higher combined success than naive OpenHands N1?

Primary estimand. Paired B4-minus-N1 difference in combined success over the frozen cohort.

Claim boundary. This is a complete-system comparison. It cannot attribute a difference to hierarchy alone because B4 also changes models, context handling, Host procedures, and recovery.

Current result. None. The preregistration is draft and unfrozen; the current 19-task candidate cohort overlaps development data.

02 / Arm definitions

The control boundary is explicit and fail-closed

N1 is naive tool use, not “B4 with one worker.” It can execute mechanical commands through its normal OpenHands shell tool, but the Arise Host cannot select, execute, or feed back any registered procedure. B4 deliberately receives those capabilities.

PatchPlan boundary. patch_plan.json contains solver-authored edit intent only and rejects unknown fields. In B4, the Host privately binds both the validated normalized plan hash and exact raw bytes to its independently frozen replay identity. That identity is not a solver field, is not required from N1, and does not enter the blinded semantic packet.
04 / Success criteria

Four gates; failure of any gate is final

success = official_mechanical AND safety_and_provenance AND host_regression AND semantic_accepted

Artifact completenessevery common deliverable exists and is non-vacuous except repo_changes.diff; patch_plan.json satisfies the strict common schemaarm-independent mechanical contract

Does not establish success: WorkCompleted, runner exit zero, agent-authored VERDICT: PASS, B4's in-run procedure PASS, file presence alone, worker-authored regression prose, or strict/generous sensitivity-mode results. The primary mechanical endpoint uses the configured primary mode.
